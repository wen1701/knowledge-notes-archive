## 🎯 核心提炼版

### 一、2026年番茄平台重大变化

- **核心变化**: 验证期和首秀规则较之前**大幅延长**
- **旧规则（对比）**: 十万字即可验证并首秀
- **新规则**: 验证期整体后移，首秀推迟至**十五万字**开始
- **平台逻辑**: 让作者投入更多时间→积累更多数据验证作品→同时让读者更久留在平台→**平台白嫖作者劳动时间**

### 二、新首秀规则时间线（关键节点）

| 阶段 | 字数节点 | 操作要点 |
|------|---------|---------|
| 普通更新期 | 1万-9万字 | 与之前相同，正常更新 |
| 文本抽查 | 1万-9万字期间 | 平台会**抽查2次**文本质量 |
| 点验证 | **9.5万字** | 开始点验证（非8万字） |
| 验证期更新 | 9.5万-14万字 | 每日更新**6000字**，连续一周 |
| 验证期流量 | 9.5万-14万字 | 日流量50或200，或递增均可 |
| 正式首秀 | **15万字开始** | 真正首秀节点 |
| 首秀冲刺 | 15万-20万字 | 尽量日更8000-10000字，流量最大期 |
| 评估节点 | **20万字** | 根据数据决定是否继续或切书 |

### 三、关键数据判断标准

- **零量情况**: 若验证期一直零量，说明**文本质量太差**（抽查未通过）
- **日收评估**:
  - 日收3元 → 建议**直接切书**
  - 日收100元 → 新人可接受则**继续写**至30万-50万字
- **核心数据指标**: 看**章节跟读率**和**毒率**，而非十万字完读等数据

### 四、数据修正与调整策略

- **十万字左右数据失真**: 因时间短、基数少，数据不成立
- **正确观测时间点**: **二十万字首秀大流量过后**再看章节跟读率和毒率
- **调整方法**:
  - 断崖式下跌 → 修改章节，加钩子
  - 钩子太弱、结构太慢 → 加快结构
  - 实在不行 → **果断切书**，不必硬扛到三十万字

### 五、行业生存逻辑

- 番茄和起点逻辑相同：**前期免费白嫖，后期按成绩分成**
- 保底合约虽有早期收入，但**想象空间小**
- 分成模式若能跑出来，收益上限更高

## 💡 关键要点总结

1. **2026年番茄新规**: 9.5万字点验证，15万字正式首秀，20万字评估去留
2. **验证期流量**: 50-200日流量正常，零量说明文本太差
3. **核心指标**: 章节跟读率+毒率，20万字后数据才可靠
4. **切书判断**: 日收3元就切，日收100可坚持
5. **平台本质**: 先用时间成本筛选作者，再决定是否分钱

## 🛠️ 实践建议

1. **存稿策略**: 首秀前提前存稿，确保15万-20万字期间能日更8000-10000字
2. **文本质量自查**: 在1万-9万字期间，确保被抽查两次能过关，避免零量
3. **数据记录**: 建立Excel表格，记录每日流量、收藏、收益，重点标记断崖下跌章节
4. **修改时机**: 不要在十万字左右大改，等20万字首秀流量过后再针对性修改
5. **切书决策**: 20万字时若日收个位数且跟读率差，果断切书开新书，不浪费时间
6. **新书验证**: 开新书时注意首秀前的章节钩子设计，确保跟读率从早期就健康

我觉得他说那个逻辑也对，就是：这个平台想让作者付出更多时间，他们就有更多数据来验证，也让读者付出更多时间留在他们平台。所以在长文方面，他一直有这样的发展趋势。

一些业内的编辑和我查资料，最后总结出来一套首秀规则。什么规则呢？从不要八万字点验证，九万五开始点验证。就是在九万字之前不要管数据，跟之前是一样。九万五开始点验证之后，你每天更六千，连续更一个星期，这时候你就十四万左右、十三四万左右了。这段时间其实还都在验证期，有五十或者二百的量，或者你的量越来越多都行。但是如果是零量，一直是零量的话，有可能是你的文本就太差了。因为他会在你一万字到你签约之后到九万字这段时间、十七万字这段，他会抽查两次。两次你抽查你的文本都太烂，啥也不是的话，不是零量。因为现在首秀太多了。

更到十四万左右的时候，这就开始十五万字，其实开始真正的首秀。现在是十五万字开始真正的首秀。然后你最好日更八千到一万，一直跟到二十万字。你的首秀这几天流量最大，你更多一点是有好处的。然后到了这二十万字，你就可以看了，切不切书呢？如果日收三块，你觉得我受不了，日收三块就不用，你就切了就完了。如果是日收一百，如果我是个新人入世的时候，七十、一百我能接受，那你就继续写，三十万、五十万这样再顺序的验证。
